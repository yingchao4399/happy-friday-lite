## 1. 本轮目标

本轮把当前 AI Core 的底层能力落实到用户每天会使用的体验中：联网失败能定位和恢复；每条对话都能独立保存、查找和继续；标题可以及时、准确地生成且尊重手动修改；打字机进入、输入、声音和图片都保持流畅；Obsidian 插件从“下载”走到“受控启用和运行”；全局 Agent 能跨 Friday 页面持续工作。

交付原则是同一版本列车内完成所有已承诺用户旅程，并用阶段门禁控制依赖。若任何一项核心验收失败，就不把它标成完成或发布完成版；继续修到通过后再生成正式交付物。计划不以增加 AI 窗口数量为目标，所有新能力必须复用并验证 AI Core 的请求、任务、权限、事件和结果链路。

## 3. 本轮范围与边界

### 3.1 本轮必须交付

1. AI 请求的连接诊断、错误分类、有限重试、流中断反馈和恢复入口。
2. 每个 AI 对话入口都能打开本范围的历史列表；历史条目独立恢复并继续原对话。
3. 对话标题与 Office 文档显示标题能够自动生成、异步优化、重试，并尊重手动命名。
4. Typewriter 分阶段加载和输入关键路径优化；空闲恢复后的声音无明显迟滞；可在打字机正文中显示和管理图片。
5. Obsidian 插件具备可理解的安装、校验、授权、启用、停用、重启、失败诊断和回滚流程；建立版本化兼容矩阵。
6. Friday 根级 Agent Dock 跨应用内页面存在，可收起、展开、切换 Agent、查看上下文与任务，并由 AI Core 在后台执行、审批和恢复任务。
7. 以上能力在同一个 Windows 安装包候选版和已有 preview.19 用户数据迁移路径中完成验证。

### 3.2 明确边界

- Obsidian 的“全兼容”作为持续兼容目标来建设。本版交付可扩展 API 宿主、兼容测试和明确支持清单，不承诺未知的私有 API、Electron/Node 依赖或任意插件组合无条件兼容。插件状态必须显示“已验证、部分兼容、待验证、不支持”，并说明阻塞 API。
- Agent Dock 的“全局”指 Friday 窗口内跨路由和支持的 Office 页面持续存在，不是本版的操作系统级置顶桌面窗口。
- Agent Dock 使用语义化应用命令、页面适配器和 AI Core capability，不控制或抢占用户真实系统鼠标。高影响写入继续走权限审批、审计、回读验证与撤销边界。
- 后台任务在 Friday 窗口隐藏或切换页面时继续运行。应用退出或重启后，只能从持久化检查点安全恢复；未获审批的副作用步骤不得自动续跑。
- 自动标题是建议和显示机制。用户自行命名的对话、Office 文件和文件路径不得被后台 AI 覆盖或静默重命名。
- 流式回复已显示部分正文后不自动盲目重发请求；保留部分内容并提供继续、重试或重新生成选项，避免重复输出和重复写入。

## 4. AI Core 完成定义

本轮以 AI Core 是否成为真实底层作为发布硬门禁，而非只看新增 UI 是否出现：

- 所有本轮新增和修改的 AI 入口（Friday 对话、Office/PDF 对话、标题生成、Agent Dock 任务、插件提供的 AI 能力）都通过 AiCoreFacade 归一化请求，再由 Context/Policy/TaskRuntime/CapabilityBus/RuntimeAdapter 执行。
- 受影响入口清单记录“入口、旧路径、目标路径、已迁移/保留原因、对应测试”。未迁移路径不得被误称为 Core 已覆盖。
- 请求携带明确的 actorId、spaceId、sessionId、requestId；长任务有 taskId、取消和状态事件。当前空间和资源范围缺失时显式拒绝或进入已定义的 global scope，不允许暗中读取所有会话。
- 计划、执行、等待审批、验证、完成/失败/取消/部分完成的状态来自 Core 任务记录。界面关闭或折叠不改变任务事实。
- 写操作先通过统一权限策略；结果包含影响资源、来源、验证结果、错误阶段和可用撤销动作。模型输出不能伪造“已完成”。
- API Key、对话正文、文件正文和敏感提示不进入诊断日志；日志仅保留脱敏后的 provider、请求 ID、阶段、耗时、HTTP 状态和错误分类。

## 5. 功能方案与用户故事

### Epic A：联网可靠性与可恢复对话

**用户价值：**网络波动时用户知道失败发生在哪一层，并能安全继续工作，而不是只看到“请检查网络后重试”。

**实施内容**

- 在模型适配层建立统一请求策略，统一连接/首字节/总时限、AbortController 取消、有限次数重试、指数退避和随机抖动。
- 将错误归类为：本地配置、DNS/连接、代理、TLS、超时、限流、鉴权、模型/请求参数、服务端 5xx、用户取消、流中断。前端按错误类型给出用户可操作的说明。
- 对尚未收到任何模型输出、且没有副作用的请求，允许有限重试；尊重 Retry-After。4xx 配置/鉴权错误不盲目重试。工具写入不通过通用网络 retry 自动重复。
- 流式开始前失败可按策略重试；已显示部分 token 后保存部分消息与中断原因，提供“继续本对话”“重试本轮”“重新生成”明确动作。恢复前确认任务、会话、模型配置和工具副作用状态。
- 提供“测试当前模型连接”入口，检查模型配置、端点可达性与最小请求。不得只以系统能否访问任意网站判断模型可用。
- 在不暴露密钥或正文的前提下，为重复故障提供可复制的诊断摘要。

**验收**

- Given 有效模型配置和短暂断网，When 网络恢复，Then 安全的无副作用请求按策略重试并返回结果，用户消息只写入一次。
- Given TLS/代理/超时/401/429/5xx 中任一种失败，When 请求失败，Then 用户能看到对应类型、阶段、可执行的下一步和请求诊断 ID。
- Given 回复已经部分流出，When 连接中断，Then 局部内容保留、消息标记为中断，不自动产生第二条重复回复。
- Given 用户点击取消，When 请求正在等待或流式输出，Then 请求停止、任务进入 cancelled，且不会残留活动流。
- Given Agent 已执行外部或本地写操作，When 底层请求失败，Then 不得自动重放非幂等操作；使用幂等键、已执行步骤回执和回读检查判断恢复方式。
- 日志扫描不得发现 API Key、完整对话正文或敏感文件正文。

### Epic B：独立对话历史与继续对话

**用户价值：**用户像使用成熟聊天侧栏一样，在各 AI 页面找到特定对话、重新打开并在原上下文中继续，不会把不同文件、Agent 或页面的历史混在一起。

**交互设计**

- 每个 AI 对话界面增加统一的“历史”入口；打开后展示该界面/资源范围内的会话列表，显示标题、最近消息摘要、更新时间、运行状态和所属 Agent/模型。
- 每条历史对应稳定 conversation/session ID。点击条目进入独立对话 thread，完整恢复消息、附件引用、模型与必要上下文；发送新消息继续追加到该条历史。
- 提供新建对话、搜索、重命名、置顶、归档、删除/恢复。Friday 全局聊天可查看全局范围；Office、PDF、笔记和 Typewriter 默认只显示当前资源范围，提供显式入口查看其他范围。
- 将 scope、scopeKey、resourceUri、agentId、modelId 等存为会话元数据。Office 的 Word、Sheets、Slides、PDF 等按资源身份隔离，不能仅按文件类型共用历史。
- 对已取消、网络中断、后台任务等待审批的对话保留消息和状态；恢复后继续同一 session/task，不创建看似新对话的副本。
- 提供平滑、可重复执行的数据迁移。旧 sessions/messages 映射到明确 scope；迁移前备份/快照，迁移后核对记录数和关联键。

**数据设计原则**

- 继续以现有 sessions/messages 为聊天事实源，避免同时写 sessions 和新的 conversation_messages 造成不一致。
- 在既有会话表和索引中按需扩展 scope、scopeKey、resourceUri、agentId、modelId、titleState、manuallyRenamed、pinnedAt、archivedAt、deletedAt、lastMessageAt 等元数据。
- 使用 parentSessionId 与 branchFromMessageId 预留“从此处分支”能力；首要验收是稳定恢复和继续原会话。分支功能只有在不会破坏迁移、删除和权限范围时才纳入本版。
- 数据库每次写入后调用 saveDb；升级与回滚路径不得丢失原始 messages、附件引用或 Office 资源关联。

**验收**

- Given 同一页面有多条历史，When 点击其中任意条目，Then 打开的消息、附件和最近状态都匹配该 session ID；切回其他条目不会串话。
- Given 用户打开一条旧历史并继续，When 发送消息，Then 新消息追加到同一 conversation/session，重启后仍可见。
- Given 用户在两个 Office 文件中分别对话，When 打开各自历史，Then 文件 A 的历史不出现在文件 B 当前列表。
- Given 一轮对话被取消或断线，When 用户重新打开，Then 能看到已完成内容、未完成状态和继续/重试入口。
- Given 执行归档、重命名、搜索或删除，When 刷新或重启应用，Then 列表状态与操作一致，删除采用可恢复策略并受权限保护。
- Given 从 preview.19 升级，When 会话迁移完成，Then 原历史可读，映射数量可核对，重复运行迁移不制造重复会话。

### Epic C：对话标题与 Office 标题

**用户价值：**历史列表和 Office 标签能快速表达内容；标题及时出现，后续可改善，但不会覆盖用户自己的命名。

**实施内容**

- 标题状态采用 pending、fallback、ready、failed、manually-renamed。手动命名状态优先级最高。
- 新对话先用首条用户消息生成短 fallback（规则清理换行、裁切和空白），不等待模型；随后在后台请求低成本标题生成，失败可重试，不阻塞消息发送。
- 标题生成仅传递最小必要上下文，使用受限标题提示与输出校验；去除 Markdown、引号、换行、敏感标识和无意义的“新聊天/总结一下”等通用标题；超长标题截短并保留可读性。
- 按应用内标题服务维护对话标题与文档标题。重复标题可附短日期/文件名区分，但不得改写正文。
- Office 文档另存 title/displayTitle/titleSource；新文档可依据用户给定标题、文档正文一级标题、工作表/演示文稿主题或摘要生成显示标题。Office 标签和最近文件列表使用同一有效显示标题。
- 文档标题、会话标题、磁盘文件名是三个独立字段。自动标题只更新未人工命名的显示标题；文件系统重命名必须由用户明确操作。外部打开的文件名保持原样，除非用户确认更名。
- 定义单一解析顺序并标记来源：用户指定 → 用户编辑的文档标题 → 正文 H1/首页标题 → 经审核的摘要标题 → 原文件名 fallback。保存时不回写覆盖用户正文标题。

**验收**

- Given 首条用户消息已保存，When 新对话创建，Then 立即出现可读 fallback，后台 AI 标题完成后更新列表无需刷新。
- Given AI 标题生成超时或模型不可用，When 对话继续，Then 对话功能不受影响，fallback 保留并显示可重试状态。
- Given 用户手动重命名会话或 Office 显示标题，When 自动生成任务迟到完成，Then 自动任务不能覆盖手动标题。
- Given Office 文档正文或工作表名可解析，When 文档尚无用户自定义 title，Then Office 标签和最近文件使用自动显示标题；磁盘文件名不被静默更改。
- Given 空文件或损坏文档，When 不能生成有意义标题，Then 回退到文件名/新建文档提示并允许用户编辑。

### Epic D：Typewriter 进入、输入与加载性能

**用户价值：**进入打字机后尽快可以输入；切换页面、加载资源或长时间停留后都不会出现明显卡顿或丢失编辑状态。

**实施内容**

- 将首屏骨架、可编辑表面、字体/主题、Nocturne 3D 舞台、插件、音频和图片资源分层。先让文本编辑可用，再逐步加载非关键视觉与媒体资源。
- 对插件/编辑器动态导入做耗时统计和错误隔离；单个插件慢或失败时不阻断基本输入。
- 对输入事件、光标、纸张进给、终端 fit 和重绘梳理关键路径；合并可合并的布局/绘制工作，避免同步测量布局、重复创建监听器、重复初始化音频或重复加载文档。
- 页面进入、离开与恢复时保存并恢复文档、选区、IME composition、安全滚动位置和撤销栈。
- 对长文、图片和高成本舞台效果采用渐进显示/懒加载；输入焦点优先级高于装饰效果。
- 用固定 Windows x64 参考机建立首轮基线后冻结 SLO。暂定验收目标：首屏达到可输入状态 P95 ≤ 2 秒；输入事件到编辑内容更新 P95 ≤ 50 毫秒；从其他主页面返回打字机 P95 ≤ 1 秒。达不到时保留实测数据和瓶颈说明，不以平均值掩盖卡顿长尾。
- Nocturne 原版体验不因性能优化而被替换成普通文本框；所有性能更改要复验键盘、IME、纸面、机头、选区和撤销。

**验收**

- Given 冷启动进入 Typewriter，When 首屏展示，Then 输入区先可用，音效、非必要插件与重型特效可在其后完成加载。
- Given 连续输入长文、切换字体/纸张和从其他页面返回，When 负载达到测试夹具标准，Then 文本、IME、选区和撤销不丢失，性能 SLO 有 P95 报告。
- Given 某个插件或效果加载慢/失败，When 用户开始输入，Then 基本编辑不等待该模块，也不重复加载或卡死。
- Given 页面隐藏一段时间后再返回，When 恢复编辑，Then 内容、光标和键盘反馈恢复，监听器和资源没有持续累积。

### Epic E：打字机声音无延迟

**用户价值：**首次按键、停顿后再次输入和从后台恢复时，打字声跟手且不需要等待网络。

**实施内容**

- 音效资源本地打包或本地缓存，不依赖网络请求；在首次明确用户手势后创建/唤醒共享 AudioContext，并预加载/解码常用音效。
- AudioContext 采用单例生命周期，正确处理 suspended/interrupted/closed 状态；窗口恢复时异步 resume，不阻塞键盘输入。
- 独立管理声音播放队列和合成；音频播放失败不能阻塞输入事件。需要限流时保留轻量机械反馈，不拖慢文字写入。
- 指标记录 keydown → 播放开始延迟、首键、持续输入、空闲恢复后首键的 P50/P95；采样只记录时序和状态，不记录输入文字。

**验收**

- Given 首次打开打字机并已发生用户手势，When 输入第一个字符，Then 文字先立即写入，音效与按键近同步且无需联网。
- Given 用户停顿 30 分钟或窗口曾进入后台，When 再次输入，Then 声音不出现明显首键延迟；空闲恢复后声音启动 P95 ≤ 100 毫秒。
- Given 系统禁止自动播放或音频设备暂时不可用，When 输入，Then 文字照常编辑，给出可理解的声音状态，不反复创建 AudioContext。
- Given 用户关闭声音，When 输入，Then 音效代码不进入热路径且设置即时生效。

### Epic F：Typewriter 图片显示

**用户价值：**用户可在打字机笔记中插入、查看和继续编辑带图内容。

**实施内容**

- 统一支持 Markdown 图片引用、应用内部图片资源 URI、粘贴、拖拽和文件选择；显示图片时保留文本编辑、选区和撤销。
- 新图片经统一资源服务保存并返回稳定资源 URI；正文引用 URI/相对路径，不默认把大图编码进正文。尊重现有笔记附件存储和同步/导出约定。
- 图片按需加载，优先缩略图；支持 alt、可选 caption、尺寸约束和原图查看。加载失败显示占位与重试，不阻塞编辑。
- 通过协议白名单和资源授权加载本地文件；拒绝任意 file:// 路径、脚本化 SVG、超限文件及未经授权的远程资源。远程图片如未来支持，必须由用户显式配置。
- 验证 Markdown、笔记预览、打字机、图片导出和 Office/知识库引用之间的兼容性，禁止一处插入导致其他视图无法打开。

**验收**

- Given 用户粘贴、拖入或选择一张图片，When 插入打字机正文，Then 图片保存为受控资源、正文引用稳定 URI，并能在退出和重开后显示。
- Given 文档含多张大图，When 首次打开或滚动，Then 图片渐进加载，不阻塞输入，失败图片有占位和重试。
- Given 外部路径或不支持格式图片，When 打开，Then 拒绝未授权资源并给出原因，原始文字和其他图片保持完整。
- Given 同一笔记在普通笔记页与 Typewriter 打开，When 编辑/保存后切换，Then 图片和正文引用保持一致，撤销及保存状态正确。

### Epic G：Obsidian 插件从下载到可运行

**用户价值：**插件管理器能准确告诉用户插件是否真的可运行；支持的插件可安装、启用、停用和恢复，失败时给出原因并保护主应用。

**实施内容**

- 将状态拆分为 available、downloaded、validated、permission-required、enabled、running、failed、disabled、update-available，并展示版本、权限、兼容等级和诊断。
- 在下载后验证 manifest、版本、入口文件、依赖、文件校验和以及最低宿主 API；不满足条件时不能标成 enabled。
- 把 Obsidian API 按能力拆分成可测试的 shim/service：Plugin 生命周期、commands、settings、Vault、MetadataCache、Workspace、Editor、事件订阅、视图注册和必要的 DOM/CodeMirror 扩展。每个能力记录宿主版本、状态、限制与测试。
- 补齐启用/停用生命周期、加载顺序、依赖检测、权限同意、设置保存、命令注册/清理和异常隔离。运行于隔离宿主，通过窄接口申请主进程能力；不得向插件暴露任意 Electron 主进程或全盘 Node 能力。
- 建立插件兼容 harness，可对同一插件版本重复执行安装、启动、命令、设置、文件读取、事件响应、停用、重启和升级用例。
- 首发兼容样本在 P0 冻结：官方 sample 插件 + 至少 10 个用户高价值、许可可接受且 API 使用有代表性的社区插件。每个插件固定版本、manifest、权限、测试结果和不支持 API。若本地已有明确常用插件清单，以用户实际需要优先排序。
- 兼容等级定义：已验证（核心用例全过）；部分兼容（主要流程可用但标明缺失 API）；待验证（未完成运行验收）；不支持（存在隔离、私有 API 或安全阻塞并说明原因）。
- 对插件崩溃设置超时/重启保护和单插件禁用入口；更新前保留旧版本，可回滚；移除时清理注册状态但按用户选择保留插件数据。
- “全量兼容”建设路径是 API 兼容矩阵 → 代表插件自动测试 → 用户可见能力状态 → 按使用与请求补足 API。对绕过公开 API 的插件应标注不支持或进行单独安全评估，不能以伪造兼容掩盖限制。

**验收**

- Given 一个合法的官方 sample 插件，When 下载、启用、执行命令、修改设置、停用、重启后启用，Then 全链路可用且状态准确。
- Given 一个能力受支持的代表性社区插件，When 在固定版本兼容套件运行，Then 测试结果与兼容等级一致，用户数据可保存、插件能被卸载/回滚。
- Given 插件调用宿主未实现 API、权限未批准或加载崩溃，When 用户尝试启用，Then 主应用不崩溃，显示具体阻断原因、日志 ID 和恢复/禁用方式。
- Given 插件升级失败，When 回滚，Then 恢复原版本和配置，其他插件与用户笔记不受影响。
- Given 插件需要网络、文件或写入能力，When 授权前查看插件，Then 用户能看到具体能力和范围；未授权能力不可调用。
- 兼容矩阵、测试样本、运行日志和已知限制随本版交付。

### Epic H：Friday 根级全局 Agent Dock

**用户价值：**用户可以随时从当前页面呼出同一个助理，折叠时不遮挡工作，展开后查看 Agent、上下文、后台任务和需要处理的授权。

**交互与运行方式**

- 在 Friday 根级 shell 放置持久 AgentDock：collapsed、expanded、running、waiting-approval、attention、offline、error 等可见状态。默认窄小、停靠在不遮挡正文的角落。
- 可在应用内容区拖动、贴边和记住位置；窗口尺寸变化、显示缩放、多显示器和 Office 页面切换时保持在可视范围。折叠/展开不移动焦点到用户输入框，不抢编辑器焦点。
- 展开卡片提供 Agent 选择、当前页面/文件/选区上下文、消息输入、运行状态、任务步骤、来源、暂停/继续/取消/重试与审批入口。切换 Agent 不改变正在运行任务的执行主体；用户发起新任务才使用新选择。
- AgentDock 展示的是 AiCore TaskRuntime 的事件和结果，不另建一套线程、权限或任务引擎。折叠或切路由后任务继续，Dock 重开后从事件流恢复。
- 页面操作通过语义化 capability（例如 note.read、office.document.create、workspace.navigate）和模块 adapter 完成；每项写操作有范围限定、幂等、审批、readback verification 和撤销能力。
- Office WebContentsView 可能覆盖 Vue；增加 Office overlay coordinator，在进入 Office 时协调 Dock 可见性、bounds、z-order、鼠标命中和安全区域。PDF、Docs、Sheets、Slides 都要分别验收。
- 仅在适配器无法提供语义化操作且用户明确授权的范围内评估代理式交互；本版本不注入全局鼠标事件，不模拟真实鼠标，也不让 AgentDock 透明拦截用户点击。
- 支持当前应用会话内后台运行；重启后读取持久化任务事件。无审批的只读任务可从安全检查点恢复；任何写入任务恢复前重新验证资源版本和授权有效期，必要时再次请求审批。

**验收**

- Given 用户切换 Friday 主页面、笔记、Typewriter 和 Office 页面，When 打开 AgentDock，Then 入口仍存在、位置合理、当前上下文准确且历史任务不丢。
- Given Dock 折叠时有任务运行，When 用户继续工作，Then 任务事件继续更新，输入和点击不被拦截。
- Given 当前任务需要写权限，When Dock 展示审批卡，Then 用户可查看对象、步骤和风险；拒绝后不执行副作用，批准后只对本任务/目标范围有效。
- Given Office 页面以 WebContentsView 显示，When 展开/折叠 Dock，Then Dock 在可交互前层且不遮住必要编辑区域；视图边界和焦点正确恢复。
- Given 用户在多个已注册 Agent 间切换，When 开始新任务，Then 新任务使用选定 Agent，旧任务保留原 owner、权限、上下文和任务状态。
- Given 应用重启后存在未完成任务，When 用户打开 Dock，Then 显示检查点、已完成步骤和继续/取消选项；陈旧授权不得被静默复用。

## 6. 公共数据与接口约定

### 6.1 现有数据源优先

- sessions/messages 作为用户对话和消息的唯一持久事实源；Agent thread 是运行时映射，不是第二份用户历史。
- Resource URI 标识笔记、图片、Office 文件及选区；会话和任务都通过稳定 ID 关联资源，而不是靠文件名或 UI 标签匹配。
- Task event 至少包含 taskId、sessionId、actorId、spaceId、eventType、occurredAt、stepId、resourceIds、safeSummary、retryable、undoTokenRef。事件正文只保存恢复所需的最小脱敏数据。
- 插件 manifest、插件版本、权限 grant、宿主 API 能力和兼容状态分开存储；更新和回滚记录必须可查询。
- UI 文案统一经 i18n；所有跨 Vue、Electron 和 Office vendor 的接口都由适配器隔离，避免某个页面组件成为权威状态源。

### 6.2 IPC 和服务边界

所有新增命令遵守项目三层边界：

1. Electron 主进程按域注册 handler，负责身份、scope、权限和持久化。
2. preload.cjs 显式暴露最小 API，不暴露通用 IPC 或任意 Node。
3. src/services/electron.js 封装类型稳定的调用，前端 store/view 只消费服务合同。

候选接口域包括 ai.network-check、ai.session.list/open/create/rename/archive/delete、ai.title.generate/retry、typewriter.media.import/resolve、plugin.validate/enable/disable/diagnose/rollback、ai.task.list/subscribe/resume/cancel/approve。实施时先搜索现有 IPC 名称并复用已有语义，避免重复注册同一能力的多个命令。

### 6.3 数据迁移与兼容

- 迁移使用版本表或幂等迁移记录；不可只依赖 CREATE TABLE IF NOT EXISTS 来模拟列迁移。
- 每次 schema 变更在复制的测试数据库上先跑旧库升级、重跑、回滚和校验；不对真实用户库试验。
- 对话迁移按 ID、消息数、附件/资源引用数和 scope 做差异核对。
- 撤销或降级时保留旧列/旧读取兼容层，至少一个支持回退的预览周期后再清理。
- Office 数据库和 HappyOffice vendor 协议需版本兼容测试；Office 构建产物用正式 build 生成，不手改生成资源。

## 7. 单版本交付阶段与依赖

所有阶段属于 3.0.6.02-preview.20 候选列车；分段推进，阶段通过后再进入下一段。

### 阶段 0：基线、复现和 Spike

- 固定 preview.19 源码提交、依赖锁、Office 子模块提交和工作区状态；记录当前本地改动，不清理用户已有临时目录。
- 对网络故障建立可复现测试矩阵：断网恢复、DNS/TLS 失败、代理、429、5xx、流中断、取消。
- 对现有 AI 入口建账，重点核对 Friday、PDF、Office、Typewriter、标题和任务 Dock 的调用链与 scope。
- 对数据库升级/回滚跑一次隔离样本。
- 限时验证两个高风险点：Obsidian sample 插件在真实隔离 host 的加载/卸载；Agent Dock 覆盖 Electron WebContentsView 的焦点与 z-order。
- 建立 Typewriter 冷/热进入、首键、空闲恢复和长文输入性能基线。
- 冻结 Obsidian 首发兼容样本清单和 Windows x64 性能参考机。

**退出条件：**复现步骤、数据备份、插件清单、Core 入口台账、性能基线和两个 Spike 结论可供开发与验收使用。未通过 Spike 的功能不得靠 UI 假状态代替。

### 阶段 1：Core 网络与任务可靠性

完成 Epic A 与 AI Core 受影响入口迁移，落实统一错误、取消、幂等、脱敏日志和可恢复任务事件。先以只读模型请求与一条可控写入任务验证错误和重试策略。

**退出条件：**网络矩阵通过；流中断不丢局部消息；写入不会重复；Core 入口台账逐项有代码路径和测试证据。

### 阶段 2：对话历史与标题

完成 Epic B/C，先完成数据库迁移、会话切换和历史恢复，再接入异步标题。历史列表采用统一服务与交互合同，各个页面保留自己的视觉布局。

**退出条件：**preview.19 历史数据无损；各 Office 文件 scope 不串；手动标题不可被 AI 覆盖。

### 阶段 3：Typewriter 性能、声音和图片

完成 Epic D/E/F。按“先输入流畅、再声音、再图片丰富度”的顺序，输入关键路径优先。每项有冷启动、热恢复、长文、媒体和回归报告。

**退出条件：**P95 SLO 达标；IME、撤销、Nocturne 舞台和普通笔记双向打开通过；图片错误和声音禁用不阻断打字。

### 阶段 4：插件运行宿主

完成 Epic G，按先生命周期、后 API 覆盖、再代表性兼容集执行。插件 host 与主应用隔离；最低能力样本通过后才开启启用按钮；完整兼容清单随版本发布。

**退出条件：**官方 sample 插件完整启停、重启与回滚通过；冻结的代表性插件集结果达到“已验证”标准；每个其他插件显示真实兼容等级和原因。

### 阶段 5：全局 Agent Dock

完成 Epic H，依赖 Core task event stream 和 Overlay Coordinator。先接入只读页面上下文与任务查询，再接审批写入和恢复。

**退出条件：**跨主路由和 Office WebContentsView 验收通过；后台任务不依赖 Dock 打开；无鼠标劫持；写入有审批、回读和撤销。

### 阶段 6：集成、发布和回退

- 回归所有受影响页面、Office 文件类型、Typewriter、插件宿主和网络场景。
- 从 preview.19 安装升级、数据迁移、重启、降级/回滚演练；覆盖已有真实数据的隔离副本。
- 跑单元/集成测试、npm run build、Windows x64 安装包构建与安装版冒烟测试。
- 发布前输出版本说明、已知限制、Obsidian 兼容矩阵、性能报告、安装包哈希和回退说明。
- 只有用户明确要求发布/上传后才执行 GitHub 发布；本文件仅为方案，不会单独触发代码提交或发布。

**退出条件：**以上用户旅程均可在安装版复验，数据库回滚可用，错误和日志符合隐私约定；所有未达项明确标为阻断，不用“基本完成”替代验收。

## 9. 风险、缓解和回滚

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 网络错误横跨模型 SDK、代理和流式实现，重试可能重复副作用 | 重复回复/文件写入或假性恢复 | 只自动重试无副作用且尚未输出的请求；幂等键、已执行回执和任务 checkpoint 驱动恢复 |
| 旧 sessions/messages 的 scope 不统一 | 历史错位或不同 Office 文件串话 | 迁移前备份；按稳定资源 ID 映射；迁移计数/关系核对；可回退旧读取路径 |
| 标题异步任务晚于人工编辑完成 | 用户标题被覆盖 | 记录 titleSource、titleState、manualRenameVersion；更新时比较版本并以人工命名为最高优先级 |
| Typewriter 舞台、输入法与重绘互相影响 | 输入丢失、音画反馈错位 | 输入模型作为唯一事实源；改变渲染节奏后跑 IME/撤销真实交互测试 |
| 图片 URI 越权或大图阻塞编辑 | 本地数据泄露、内存/卡顿 | 资源服务统一授权、协议白名单、大小限制、懒加载和失败隔离 |
| Obsidian 生态依赖私有 API、Node/Electron 或插件间约定 | 插件启用率低或安全隔离失效 | 明确兼容等级；插件 host 隔离；能力代理白名单；先做样本与自动 harness，不声称全量兼容 |
| WebContentsView 覆盖全局 Vue Dock | Office 中入口不可见/不可用 | Office overlay coordinator 做视图边界管理；分别覆盖 PDF/Docs/Sheets/Slides 并测试焦点 |
| 版本范围过大导致质量被压缩 | 安装包带有未验收功能 | 以阶段退出条件为硬门禁；失败则继续预览迭代，不跳过测试、不宣称全部完成 |

回滚策略：所有新用户界面均可由 feature flag 隐藏；数据库迁移采用向前兼容与恢复快照；插件更新保留旧版本；正在执行的 Agent 任务只可在可验证检查点暂停/恢复；回退版本保留消息、笔记、图片资源及 Office 原始文件。
