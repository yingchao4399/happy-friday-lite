# Friday Preview.22 产品需求文档（PRD）

**产品**：Happy Friday Lite / Friday 全局助手  
**版本**：3.0.6-preview.22 规划  
**文档状态**：研究后需求冻结稿，待技术评审与实现排期  
**日期**：2026-10-30（Asia/Shanghai）  
**前置文档**：问题分析与根因报告、研究方案与验证计划、技术设计与架构方案

---

## 1. 背景

用户在主对话中可以正常使用 DeepSeek，但在 Office 助手中经过一次工具调用后反复出现“网络有问题，无法连接 AI 服务”。同时，Office、笔记、知识库、日程和全局 Dock 的会话历史各自使用不同的展示和存储方式，导致历史记录不完整、无法按条目恢复、缺少统一的新建对话按钮、侧边栏遮挡内容和输入框不可用。

Typewriter 还存在长文输入卡顿、流式输出导致整页重渲染、图片只能显示在正文上方、不能在正文中自由拖动缩放、图片与纸张材质及灯光不融合等问题。

本版本的核心任务是重建可靠的 AI 请求边界、统一所有对话入口的会话体验、建立可拖动且不遮挡内容的悬浮侧边栏，并将 Typewriter 图片改造成正文节点。产品视觉基线继续沿用原版 Friday 的颜色、圆角、字体和动效节奏，只统一交互契约和布局行为。

## 2. 产品目标

### 2.1 目标

- Office Docs/Sheets/Slides/PDF 助手在 DeepSeek 配置下能够稳定完成普通问答、工具调用、工具结果续轮和最终回答。
- 422 参数错误能够准确说明协议或配置原因，不再把所有失败提示成网络问题。
- 主对话、Office、笔记、知识库、日程和 Dock 的每个 AI 窗口都拥有一致的悬浮历史侧边栏、搜索、选择、恢复、归档和“新建对话”入口。
- Dock 可在页面任意位置拖动，展开不卡顿，具备可用输入框、中文输入、发送、取消和历史恢复能力。
- Typewriter 进入页面后核心编辑组件尽量一次性加载并立即可交互，长文编辑保持流畅；图片显示在正文中与笔记模块相同的锚点位置，默认小图，可鼠标拖动缩放，重开后位置和尺寸保持一致，并能与纸张材质和灯光融合；底部打字滑块在远距离点击时从当前位置丝滑滑到目标位置。
- 设置中的 Friday 全局助手开关、形象、分身模式和 agent 切换具有真实运行语义，而不是只有视觉开关。

### 2.2 非目标

- 本版本不重新设计 Friday 的品牌视觉和整体导航结构。
- 本版本不承诺所有 provider 都支持 DeepSeek thinking 工具续轮；能力取决于 provider 能力声明和验证结果。
- 本版本不把未经验证的云同步、跨设备历史合并作为默认能力。
- 本阶段研究文档本身不修改源码、不生成安装包、不上传 GitHub；安装包和发布动作必须在实现与发布门禁全部通过后执行。

## 3. 用户与核心场景

### 3.1 Office 用户

用户打开文档并让 Friday 摘要、改写、生成表格或执行工具。助手应完成请求，不因 tool call 续轮丢字段而出现 422。用户可打开当前文件的历史侧边栏，点击某条记录恢复完整上下文，或点击统一的新建对话按钮开始独立会话。

### 3.2 多模块工作用户

用户在主对话、笔记、知识库、日程之间切换。每个模块的历史只展示自身 scope 的会话，点击历史项后加载对应消息和 agent 配置，不串台；侧边栏外观、位置、关闭方式和新建按钮保持一致。

### 3.3 全局 Dock 用户

用户在任意页面拖动 Dock 到不遮挡内容的位置，点击展开后立即看到与其他模块一致的“新建对话”和“会话历史”按钮、历史列表和输入框，输入中文并发送。展开、流式输出和切换历史不应造成明显卡顿。Dock 隐藏后可从设置或快捷方式恢复。

### 3.4 Typewriter 用户

用户在长文中插入图片。图片出现在正文锚点，位置规则与笔记模块一致；默认显示为小图，用户拖动控制点改变大小或对齐，图片跟随纸张材质和灯光呈现。关闭并重新打开文档后，图片仍位于原段落、尺寸和效果一致。

## 4. 统一交互原则

1. **同一动作同一位置**：所有 AI 窗口使用相同的历史入口和“新建对话”按钮。
2. **上下文可见**：界面显示当前 scope、文件/笔记名称和 agent，避免用户误以为不同窗口共享了错误历史。
3. **失败可行动**：错误提示必须说明是网络、认证、参数、工具或模型能力问题，并提供重试、切换模式、新建会话或打开设置等动作。
4. **内容优先**：悬浮层默认不覆盖正文关键区域，拖动后记住位置并在窗口变化时自动回到可视边界。
5. **原版视觉一致**：颜色、图标、圆角、阴影和动效沿用原版设计 token，只修正布局、焦点和状态行为。

## 5. 功能需求

### FR-01 AI 请求与 Office 续轮

**描述**：AI Core 必须将完整的 canonical transcript 发送给 provider。

**要求**：

- assistant 的 `tool_calls`、tool 的 `tool_call_id`、函数名和 arguments 不得在能力校验或 IPC 中丢失；
- DeepSeek thinking 关闭时，工具续轮可稳定完成；
- thinking 开启时，只有在 `reasoning_content` 能保存、恢复并通过 provider 校验后才允许使用；
- 422 错误显示为参数/协议错误，包含简化的字段路径和请求 ID，不显示“检查网络”；
- 网络错误、认证错误、模型能力错误分别显示不同的可行动建议；
- Docs、Sheets、Slides、PDF 使用同一套能力和错误合同。

**验收**：连续执行 100 次工具续轮，成功率 ≥99%；任何 422 均可在日志中定位到 provider、status、参数路径和 requestId。

### FR-02 统一会话历史

**描述**：六类入口统一使用 ConversationStore 和悬浮历史侧边栏。

**覆盖范围**：主对话、Office agent、笔记、知识库普通对话、知识库 Agent 对话、日程助手、Dock。

**要求**：

- 每个入口都有历史按钮、搜索、排序、归档和同款“新建对话”按钮；
- 点击历史项加载完整消息、标题、更新时间、scope 和 agent 配置；
- 历史记录按 scope/scopeKey 隔离：Office 按文件，笔记按笔记，知识库按知识库，日程按日历/事件，Dock 按全局；
- 新建对话先持久化再切换 UI，不能产生空壳记录；
- 连续快速点击不同历史项时，最后一次选择优先，旧请求不能覆盖新内容；
- 删除、归档和重命名结果在所有使用该会话的入口即时一致；
- 迁移期间旧数据只读可回退，禁止静默丢失消息。

**验收**：每个 scope 至少准备 20 条历史；随机点击、刷新、重启后记录可恢复且无跨 scope 串台。

### FR-03 统一悬浮侧边栏

**描述**：历史和助手面板均为 body-level 悬浮侧边栏。

**要求**：

- 通过统一 overlay root 管理层级、定位和焦点；
- 默认从当前窗口右侧滑出，避开系统安全区和主要编辑区域；
- 用户可以拖动 Dock 和侧边栏，窗口缩放、DPI 切换、多显示器切换后自动保持在可见范围；
- 点击遮罩关闭，点击面板内部不关闭；Esc 关闭当前最上层面板；
- Office 中历史边缘不得被另一个侧边栏遮挡；
- 面板打开后焦点按可访问性顺序进入搜索/会话列表/新建按钮/输入框。

**验收**：100%、125%、150% DPI，单屏和双屏各执行拖动、缩放、打开历史、选择会话测试；关键按钮无重叠、不可点击区域和跳动。

### FR-04 Dock 输入与状态

**描述**：Dock 展开态必须提供完整对话能力。

**要求**：

- 展开态显示当前标题、与其他模块同款的“会话历史”按钮、同款“新建对话”按钮、消息列表、输入框、发送和取消按钮；
- “新建对话”调用统一 `ConversationStore.create({scope: 'dock', scopeKey: 'global'})`，成功后切换到新 conversationId；
- “会话历史”调用统一 `openHistory({scope: 'dock', scopeKey: 'global'})`，打开同一悬浮侧边栏并加载 Dock 历史；
- 两个按钮在无历史、加载中、发送中、错误、键盘聚焦和高 DPI 状态下均可见、可点击、可读，视觉与其他模块按钮一致；
- 收起态显示 Friday 形象和未读/流状态；展开态显示当前标题、历史入口、消息列表、输入框、发送、取消和新建按钮；
- 支持中文 composition 事件、Enter 发送、Shift+Enter 换行、附件/图片失败提示；
- 提交时固定 conversationId 和 agentId，流式响应只写入该会话；
- 展开动画和流式消息采用增量更新，目标 60fps，P95 首次展开 ≤150ms；
- 拖动 Dock 时不触发消息面板重排，不抢占输入焦点；
- Dock 的隐藏/显示由设置持久化，重启后生效。

**验收**：连续发送 30 条中英文消息，输入不丢字、不重复、不串会话；展开、拖动、历史切换和发送过程中无明显卡顿。

### FR-05 Friday 全局助手设置

**描述**：设置页增加 Friday 全局助手专属设置。

**字段与语义**：

- `visible`：全局 Dock 显示/隐藏；
- `appearance`：形象、尺寸和主题资源；
- `cloneMode`：选择预定义分身 profile，并显示能力说明；
- `agentId`：选择实际执行的 agent，下一轮请求使用该 agent；
- `defaultScope`：Dock 新建会话默认 scope；
- `keyboardShortcut`：显示/隐藏或聚焦 Dock 的快捷键。

**要求**：设置修改后立即更新已打开面板；agent 切换不能伪装成只换头像；历史记录保留创建时的 agent 元数据。

### FR-06 Typewriter 长文性能

**描述**：优化打字机编辑和 AI 流式渲染。

**要求**：

- 进入 Typewriter 后编辑器壳、正文节点渲染器、输入/选区管理、核心工具栏、保存状态和图片节点控制器尽量在首屏一次性加载并可交互；
- 图片原图解码、非当前视口资源和导出适配器可后台预热，但首次交互不得重新挂载整棵编辑器树；
- 文档编辑状态使用增量 patch，禁止每次按键重建整篇 Markdown；
- 长文（≥50,000 字）输入时主线程长任务 P95 <50ms；
- AI 流式输出按帧批量刷新，首 token 到首屏 ≤1s，持续输出保持 ≥30fps；
- 可视区域外内容和图片使用虚拟化/懒加载；
- 自动保存与编辑解耦，编辑不因磁盘写入卡顿；
- 重开文档后内容、光标附近上下文和图片节点一致。

### FR-07 Typewriter 正文图片

**描述**：图片成为正文节点，位置规则与原笔记模块一致。

**要求**：

- 插入图片后出现在当前光标/段落锚点，不显示在顶部独立图片条；
- 正文图片的宽度、对齐、段间距和锚点与笔记模块图片相同；
- 默认小图显示，用户可通过鼠标控制点自由缩放，最小 96px，最大不超过正文宽度；
- 支持左/中/右/行内对齐和保持比例；
- 图片与纸张材质和灯光融合，提供受限的强度、色温、阴影调节；
- 图片资产走安全协议，加载失败显示可重试占位节点；
- 尺寸、位置、对齐、光照和 alt 文本可保存、撤销、重做和导出；
- Typewriter 与笔记模块在同一正文位置规则下渲染，不能出现“Typewriter 图片在上方、笔记图片在正文”的差异。

**验收**：插入 10 张不同尺寸图片，随机拖动缩放、移动光标、撤销重做、关闭重开、导出，位置和尺寸误差 ≤1px（同一 DPI）。

### FR-08 Typewriter 打字滑块物理过渡

**描述**：当用户从静止状态点击远处正文文字时，底部打字滑块必须从当前视觉位置连续滑向新的 caret 位置，符合物理连续性。

**要求**：

- 真实 caret、选区和滚动目标立即定位正确，滑块动画只提供视觉反馈；
- 近距离点击使用短时 ease-out，远距离点击使用受限的平滑过渡，最大动画时长 300ms；
- 动画中再次点击时从当前视觉位置重新规划，不跳回旧起点、不瞬移、不回弹；
- 使用合成属性或等价方案，动画期间不触发整篇文档重排；
- 遵循 `prefers-reduced-motion`，减少动态效果时关闭位移或缩短为不超过 100ms 的淡入；
- 鼠标点击、触控板、键盘移动和滚动导致的目标变化使用同一状态机。

**验收**：远距离点击 100 次，0 次瞬移、回弹或明显速度突变；动画 P95 ≤300ms，帧率 ≥55fps，且不影响输入、撤销和保存。

### FR-09 图片与附件错误

- 图片下载/读取失败必须显示 assetId、失败原因类别和重试按钮；
- 远程图片未经策略允许不得加载；
- 超大图片先显示缩略图并在后台解码原图；
- 图片失败不能阻塞文本编辑和 AI 对话。

## 6. 非功能需求

### 性能

- Office 面板首次打开 P95 ≤200ms；Dock 展开 P95 ≤150ms；
- 历史列表首屏 P95 ≤300ms，加载会话正文 P95 ≤500ms；
- Typewriter 核心组件冷启动后首屏可交互 P95 ≤1.5s，0 次编辑器空壳或明显布局跳变；
- 50,000 字 Typewriter 输入主线程长任务 P95 <50ms；
- 流式输出期间页面帧率 ≥30fps，普通设备不出现持续 200ms 以上冻结。

### 可靠性

- Office 工具续轮成功率 ≥99%；
- 会话追加消息采用幂等 messageId，断电或重启后不重复；
- 迁移校验 100% 通过后才能切换默认读取路径；
- 关键错误可通过 requestId 和 conversationId 追踪。

### 安全与隐私

- 日志脱敏 API key、完整文档、用户消息和图片内容；
- 本地图片使用 `friday-asset://`，阻断任意 `file://` 访问；
- agent profile 的工具权限由主进程校验，UI 不能自行扩大权限。

### 可访问性

- 所有悬浮层具备键盘导航、焦点陷阱、Esc 关闭和屏幕阅读器标签；
- 输入框支持中文 IME、撤销和快捷键；
- 颜色对比度、点击热区和动态效果遵循原版可访问性基线。

## 7. 数据与迁移要求

- 建立统一 conversation、message、asset、agentProfile 和 overlayPreference 数据结构；
- 旧 Friday SQLite、Office ProjectStore 和组件历史进入迁移清单；
- 迁移按 scopeKey 做重复检测，保留 sourceId 与 targetId 映射；
- 迁移失败时入口可回退到只读旧数据并提示用户，禁止把失败当作“没有历史”；
- Dock/设置偏好与会话数据分离，卸载或清理缓存时按用户确认处理。

## 9. 发布门禁与交付物

只有以下条件全部满足，才允许生成安装包和上传 GitHub：

1. 四份研究/设计文档已评审并形成变更记录；
2. AI Core 协议、会话存储、overlay、Dock 和 Typewriter 契约测试通过；
3. Windows 安装版完成冷启动、升级、回滚和真实 DeepSeek 回归；
4. 性能指标、日志脱敏和数据迁移报告齐全；
5. 用户反馈中的 Office 错误、历史统一、Dock 输入和 Typewriter 图片位置均有可复现的验收证据；
6. 安装包、校验和、版本说明和 GitHub 发布说明相互一致。

发布后必须保留：安装包下载地址、SHA-256、构建日志、测试报告、已知限制和回滚包地址。

## 10. 风险与后续

- provider 对 thinking/tool calling 的协议差异可能要求按模型能力动态降级；
- 旧会话数据结构复杂时，迁移需要分批开启和可观测回滚；
- 富文档模型会增加导出适配成本，必须先保证编辑器内正文位置和持久化，再扩展复杂导出；
- Windows 多显示器和系统缩放组合需要在真实设备上验证，模拟器结果不能替代安装版验收。

本 PRD 的完成标准是：每一项用户反馈都能映射到数据边界、交互行为、验收指标和发布门禁；没有只改文案、重试或局部 CSS 的替代方案。
