PDF 转 Word 修复 PRD

日期：2026-11-05

关联文档：故障研究报告、修复方案

1. 文档状态

本文定义 PDF→DOCX 小版本的产品需求和验收标准。当前状态为待修复。原有 GenOffice 总体分析、总体方案和总体 PRD 继续保留，负责后续版本的范围和决策。本 PRD 不改写总体文档，也不把总体升级作为本次修复的前置条件。

2. 用户问题与成功定义

用户在 Friday 中打开一个 PDF，选择“转换为 Word”，当前可能没有 DOCX、转换失败无清晰原因，或生成内容不是当前已保存版本。修复后，用户可以完成目标选择、看到转换进度和结果，生成的 DOCX 能被 Friday Docs 或 Microsoft Word 打开。扫描页和 OCR 不可用时必须明确提示退化内容。

本版本的成功定义是 PDF→DOCX 端到端可用。文件可打开、源 PDF 不被覆盖、取消可恢复、密码和资源错误可理解、安装版无需 vendor 目录即可运行。

3. 范围和优先级

范围 优先级 说明
PDF renderer 到 Friday main 的 pdf:convert-office 链路 P0 必须真实调用并返回稳定结果
普通文字 PDF 转 DOCX P0 关键段落、表格、图片可读取
dirty PDF 保存后转换 P0 转换内容来自已确认快照
加密 PDF 密码重试和取消 P0 保留空格，不记录密码
扫描 PDF、OCR 和图片退化提示 P0 明确逐页状态

PDFium、OCR 和 converter 的安装包资源 P0 移目录和断网条件可运行
PDF→XLSX、PDF→PPTX、打印和全量 Office 升级 本版本不纳入 另行规划

4. 功能需求

FR-PDF-01 入口与权限

PDF editor 的转换菜单和 ribbon 入口都调用 pdfApi.convertOffice('docx')。主进程只接受当前活动 PDF tab 的 sender，旧 tab、非 PDF sender、未知 format 和缺少源路径都返回稳定错误。renderer 不得自行指定另一个文件作为源。

FR-PDF-02 保存快照

转换开始前检查 dirty 状态。存在未保存编辑时请求保存并等待持久化。保存超时、renderer 销毁、用户取消和源路径变化都停止转换。目标 flushAll 是否需要由专项测试决定，不能在没有证据时把未 Done 的表单值标记为已支持。

FR-PDF-03 目标选择

默认目标为源文件同目录的同名 .docx。目标路径支持中文、空格和长路径。取消目标选择不创建文件。目标不能与源 PDF 解析到同一规范化路径。

FR-PDF-04 转换执行

主进程调用本地 convertPdfFileToDocxLocalWithPrompt 或等价适配器。转换器使用 PDFium WASM，存在可用 helper 时使用平台 OCR。转换过程提供开始、页进度、验证和完成状态。长文档转换不能无限阻塞窗口。

FR-PDF-05 密码

普通 PDF 先尝试无密码读取。收到 password-required 后显示密码框。错误密码允许重试，密码中的前后空格必须保留，取消密码立即停止且不生成半成品。密码不得写日志、IPC 事件或错误详情。

FR-PDF-06 输出验证

写入目标前先写同盘临时文件。验证目标为非空 DOCX ZIP，包含 [Content_Types].xml 和 word/document.xml。验证失败时删除临时文件并保留已有目标。验证通过后原子替换，之后再打开 Friday Docs。

FR-PDF-07 质量提示

转换完成后检查 pageResults 和 scannedDocument。纯文字页提示可编辑文本。OCR 页提示机器识别结果需要校对。整页图片页说明该页保留为图片，不能显示为完全可编辑。提示中应包含页码，使用现有中英文 i18n。

FR-PDF-08 生命周期

同一 PDF 同时只能有一个转换任务。重复点击显示进行中。切换文件、关闭 tab、关闭主窗口或替换活动 tab 时，任务取消或进入有界清理流程。异步返回后必须确认原始 entry、sender 和目标仍然有效，迟到结果不能写入另一个文档。

FR-PDF-09 资源

正式包必须包含 PDFium WASM、converter 需要的 Node bundle、Windows OCR helper（若构建该平台）和许可证。运行时优先从 process.resourcesPath 定位。移除 vendor 和源码后仍能完成普通 PDF 转换。

FR-PDF-10 错误反馈

错误至少区分入口未接线、资源缺失、密码错误、PDF 损坏、格式不支持、保存失败、目标被占用、用户取消、超时和未知异常。用户界面显示可理解的文案，日志保留稳定错误码和脱敏上下文。

6. 非功能约束

转换过程不得把 API Key、PDF 密码或完整 PDF 内容写入普通日志。输出失败不能截断已有目标。Windows 中文和空格目录必须可用。界面文案通过 zh-CN 和 en-US i18n 提供。主进程和 renderer 之间只传递必要的状态、错误码和进度。

7. 验收门槛

开发环境通过 AC-01、AC-02、AC-05、AC-07、AC-12、AC-14 后才可进入安装包验证。安装包必须通过 AC-01、AC-02、AC-08、AC-10、AC-11、AC-15、AC-16、AC-18。任一 P0 用例失败都不能把该版本标记为 PDF 转 Word 修复完成。

8. 当前完成度

需求、故障链和验收样本已经定义。当前代码尚未按本 PRD 修复，真实安装包转换和 DOCX 产物尚未产生。本轮文档完成不代表功能完成。

9. 用户交互细节

转换按钮在任务开始后进入忙碌状态，重复点击不会启动第二个任务。保存 dirty PDF 时先显示保存阶段，用户取消保存即可结束，不弹出无意义的目标选择框。目标选择取消返回 PDF 页面，不改变其 dirty 状态。转换过程中显示页进度，无法计算总页数时显示不确定进度。

成功后显示目标文件名和打开 Word 文档动作。若目标已存在，覆盖确认必须在开始写目标前完成。转换过程中不自动关闭源 PDF。成功打开 DOCX 后，源 PDF 仍可单独关闭或继续编辑。

10. 格式保真口径

PDF→DOCX 是版面和内容转换，不承诺恢复原始 PDF 生成软件的编辑对象。验收关注阅读顺序、关键文字、页数近似、表格内容、图片内容和 DOCX 可编辑性。复杂分栏、嵌套字体、公式、批注、签名、动态内容和扫描识别误差需要在样本记录中单独说明。

扫描页面有三种可见结果。文字层成功时输出可编辑段落。OCR 成功时输出机器识别文字并提示校对。OCR 不可用或失败时可保留整页图片，提示具体页码。产品不能把图片页计为可编辑文本，也不能因存在图片就把整个转换标记为失败。

12. 证据格式

每个 AC 用例需要保存候选版本、命令、退出码、脱敏日志、源 SHA256、目标 SHA256、DOCX 解压检查结果和必要截图。测试结果使用 pass、fail、blocked 三态。blocked 必须说明是环境依赖缺失、样本缺失还是产品问题，不能折算为通过。

13. 发布和回退条件

只有 AC-01 至 AC-18 中所有 P0 条件通过，且安装包能在无 vendor 的中文空格目录运行，才可标记“PDF 转 Word 修复版”。如果仅开发目录通过，版本状态写为“开发候选”。如果普通文字 PDF 通过但 OCR 或资源验证失败，必须在发布说明中列出退化范围并继续阻断本 P0 修复。

回退时恢复与资源目录匹配的上一候选包。用户原 PDF 不需要迁移，因为转换不会改写源文件。对已生成的 DOCX 保留用户文件，不由回退脚本删除或覆盖。
