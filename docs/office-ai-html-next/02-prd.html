Friday AI HTML 融合产品需求文档

状态：研究与拟实施要求，尚未实施或验收。日期：2026-11-06。适用产品：Happy Friday Lite 下一版 Windows 桌面候选。本文保留既有总体升级和 PDF 专项文档，不覆盖其历史结论；具体技术接口和版本审计以本次配套技术对接文档、融合方案及实施时冻结的代码为准。

1. 目标与判断口径

用户能够在 Friday 中创建、打开、编辑、预览、让 AI 生成或修改、保存和导出 HTML 文档，体验达到选定的 GenOffice 开源 AI HTML 应用同等功能，而不只是能打开网页或回答聊天。Friday 可保留自己的品牌、标签、配置、权限和主助手界面；用户任务、可观察的操作阶段、结果格式及失败恢复需要与冻结目标等效。

本轮只产出研究及方案文档。本文列出的能力、数字、验收和路线是目标合同或拟验证假设，不表示 Friday 现在已实现，也不是本轮已测试通过的结论。既有四类 Office 和 PDF→Word 的能力、用户数据和历史必须回归，不以新模块上线为由牺牲已有行为。

1.1 对等目标的冻结

  1. 既有研究以 GenOffice v0.12.600、commit 1a0fcec971c714d11777cbd5c68da1c933572d14 为历史参考，其 HTML-01 至 HTML-12 均为 P0，详情保留在总体报告和 PRD。它们是本次需求基线，实施时不得无故删减。
  2. v0.12.852 是之前观察到的升级候选，不等于已批准、已集成或永远最新。启动研发前重新核实官方 tag、tag 指向的完整 commit、来源、许可及发布时间，记录查询时间，确认具体目标；评估其相对 v0.12.600 的 HTML 模块、依赖和安全变化。若选用其他目标，同样冻结完整身份和逐项差异；不得把未经审查的目标行为写成已经证实的现状。
  3. 建立目标版本的逐项能力台账，覆盖菜单、工具栏、快捷键、上下文操作、AI tool、IPC、资源、导出、自动化和实际条件。已有 HTML-01 至 HTML-12 为父编号，新增细项采用稳定子编号。分别统计映射率和通过率；未知、条件阻塞、未实现或待验收均不是通过。
  4. 在相同平台、相同输入及同类别的有效模型和外部服务配置下比较。生成内容不要求逐字或逐像素相同，但用户能完成的工作、文件格式、工具动作、必要确认、取消和恢复应等效。上游源码或菜单存在、mock 成功、空数组、unsupported 均不能证明正常功能可用。

2. 用户、场景与范围

用户包括编辑现有 HTML 的用户、用自然语言生成报告/活动页/仪表盘的用户、需要本地预览或导出文档的用户，以及需要反复编辑并继续 AI 会话的用户。

主要场景：新建空白 HTML；打开本地 .html/.htm；在源码、分屏、预览间编辑；选择元素后要求 AI 修改；提供附件让 AI 规划并生成页面；在预览运行合法交互；保存、另存、演示、导出 PDF/DOCX/单文件 HTML 或打印；关闭并重新打开文档继续工作。

本版 P0：完整接入冻结目标的 AI HTML 应用及其用户可达能力，包括 12 组功能、有效服务条件下的搜索/图片等工具、Friday 文件与会话集成、GUI 和目标支持的自动化、真实安装版验收与四类 Office 回归。任何上游能力缺口不得以“只是增强项”或不可用占位静默放行。对于目标新增功能，完成差异盘点并纳入台账。

边界：本专项不自动承诺 AI Markdown、全部 GenOffice 升级或任意格式互转；原有总体需求保留。没有明确证据时不承诺 HTML→HTML headless 或独立 HTML read/apply CLI。PDF 转 Word 是已有专项，相关未关闭验收按其独立账本处理，本功能不得破坏它。桌面环境与所选外部服务有各自限制，不能因文本模型可用就声称图片生成、联网搜索均已可用。

3. 产品原则

  • HTML 源码是文档真相：可视操作、AI 修改、撤销、保存及导出都反映同一版本的源码，不能以预览 DOM 快照覆盖源码，尤其是脚本产生的动态节点。
  • 文件与会话身份明确：基于稳定文档/标签身份及规范路径，而非仅凭文件名；窗口或标签切换不能把操作、历史或产物发给另一文档。
  • 区分生成、保存和打开：未保存的编辑、已写入文件、导出成功、已在目标应用打开分别表述；失败或取消不得报成功，也不能截断旧文件。
  • 按能力真实告知：模型、搜索、媒体、网络、权限分别判断；真实零结果、服务未配置、权限不足、网络或配额错误是不同状态。
  • 兼容原入口：原 HtmlViewer 和系统打开偏好继续可用；显式的“用 AI HTML 编辑”与只读查看区分，既有偏好迁移、默认行为与回退规则须在实现前冻结和验证。
  • 保持上游功能的安全边界：保留合法的页面脚本和交互，通过隔离和权限控制保护 Friday 宿主、用户文件与密钥，不能靠一律关闭脚本代替等效实现。

4. 用户流程

4.1 创建与编辑

  1. 用户从 Office 新建 AI HTML，或通过明确的编辑动作打开授权文件。显示文档标题、保存状态与编辑入口。
  2. 用户在源码、分屏或预览模式切换；在可映射的静态元素上选择、编辑或使用工具栏，操作反映到同一个源码文档，并可撤销/重做。
  3. 用户选择保存或另存，系统核对文档身份与目标；新文档要求选择位置；需要替换已有文件时按目标合同确认；失败或取消保留当前未保存内容。
  4. 关闭含未保存修改的文档时提供保存、丢弃、取消；保存中仍发生新编辑时，不得把新版本错误标记为已保存。

4.2 AI 生成与修改

  1. 用户通过 HTML 内 AI 输入需求、选区或附件；系统绑定当前文档和当前版本，列出实际可用的模型及工具。
  2. 对整页任务，根据目标行为进行澄清、展示可编辑的 brief/风格方案并等待用户确认，再启动独立 writer 生成流式草稿；对局部修改使用可追踪工具操作而不是把聊天文字冒充文档修改。
  3. 用户可停止、决定保留或放弃中断草稿；提供可见的失败和重试反馈。若生成期间用户修改文档、切换或关闭标签，旧结果必须经版本和 owner 校验，不得覆盖较新的编辑或写入其他文档。
  4. 系统显示操作完成与否及未保存状态；仅当确实写盘后才能称文件已保存。AI 修改前快照和撤销按目标能力呈现，不宣称内存快照是永久版本库。

4.3 导出与恢复

导出从确认的当前文档版本取数据，必要的样式预览先提交；用户选择目标并处理覆盖，再生成、校验并报告路径、限制及打开状态。输出已有文件、目标文档正被打开且 dirty、用户取消、转换失败或打开失败时，保留原文件及已生成文件的真实状态；重试打开不应重新覆盖或重复转换。

HTML-11 输出/打印 按目标支持 GUI DOCX、PDF、单文件 HTML、系统打印及 HTML→PDF/DOCX 自动化。 从已保存与 dirty 状态分别输出并实际打开；逐格式验证资源和内容、覆盖/取消/错误保护；打印与 PDF 分别实测；无开发源码目录的安装包运行自动化并校验文件与退出结果。
HTML-12 资产/隔离 合法相对资源及资源迁移工作；运行不可信 HTML 时宿主、密钥和非授权文件受保护，保留目标合法交互。 首存/跨目录另存、资源重写、失败回滚及清理；路径穿越/别名/符号链接越界拒绝；脚本、链接、表单、弹窗、网络请求按明确策略实测；不能访问 Friday preload/Node/密钥或任意写盘。

5.1 具体工具与服务的产品含义

历史 v0.12.600 清单为 get_outline、read_source、apply_ops、ask_clarification、plan_page、write_document、search_images、generate_image、web_search、read_attachment；目标版本冻结后重新核验实际清单、可用条件和返回。附件读取或图片抓取的底层 IPC 不应误写成同名 Agent 工具。

用户能够在设置或操作状态中区分：文字模型未配置、不支持工具调用或多模态；搜索未配置或网络不可用；图片生成未配置、配额或服务错误；有配置但搜索确实无结果；文件未授权；取消。可恢复错误提供重试或配置入口，用户无需反复触发必然失败的工具。授权外请求、超时及取消不能被伪装为零结果。

目标服务在有效配置下支持的任务必须有真实请求和结果验收。模型文字、网页搜索、图片搜索、图片生成和本地资产分别判断；用户配置、账号、费用及网络是实施与测试前置条件。界面和日志不展示密钥，不能为兼容上游工具新建一份明文密钥配置；统一配置的具体实现由技术文档定义并验证。

5.2 精确输出限制

历史参考中，单文件 HTML 只尝试内联可读取的本地图片，并报告未能内联的项目，不等于任意网页及其外部资源的完整离线归档。系统打印允许脚本、PDF 导出使用不同脚本策略，动态页面在两者不保证相同；DOCX 输出有网页布局和 CSS 的转换限制，不承诺任意网页完美还原。以目标版本实测为准，用户应在导出结果中看到实际限制或失败，而不是错误的全保真承诺。

GUI 导出、系统打印、应用 headless 与现有 Friday CLI/agent 路由分别验收。对 CLI 需核对实际命令、目标格式、机器可读结果、退出状态和产物，不能仅以 vendor 存在导出函数推断可用。不得把受限 HTML 片段导入 DOCX 路线称作完整网页转 DOCX 的等价实现。

6. 一致性、授权和安全

  1. 明确文件 owner、文档 ID、快照/修订号和调用方；每次异步 AI 或导出操作从开始到提交保持身份绑定。保存、另存、关闭、外部修改和冲突处理需要定义原子行为，Windows 大小写、路径别名、符号链接及同名文件都应覆盖。
  2. 执行写入、覆盖、访问附件或资源及联网请求时，按 Friday 宿主的授权模型执行；授权范围、取消和超时可追踪。模型生成内容和被读取网页均为不可信数据，不能把其中的指令提升为用户授权。
  3. 网页作者脚本运行在隔离预览中。对资源访问、外链导航、弹窗、文件协议、网络、下载及打印设置清晰规则，并在保持目标合法交互的同时验证边界。上游 iframe 的历史 sandbox 配置不是“任意 HTML 绝对安全”的证明，实施须重新核验目标版及 Electron 组合。
  4. 聊天、诊断、任务状态及日志按最小必要原则处理文档正文、路径、附件与密钥；必要的脱敏不应破坏正常文件。遥测和支持包若存在，需声明收集范围与授权，不记录明文密钥或未授权正文。
  5. 服务不可用时隐藏或禁用不可执行动作并说明原因；服务正常配置后对应能力必须真的可用。开发和运行时出现能力声明与 handler 不一致应阻断发布，而非由模型猜测或循环重试。

7. 非功能需求

  • 可靠性：失败、取消、崩溃或目标占用不破坏源和已有目标；跨目录资产处理有可检查的回滚；未保存状态不会因异步完成而被清除。
  • 性能：对小、中、大 HTML、长对话、较多 DOM 元素和图片样本记录打开、编辑、预览刷新、内存、AI 流式和导出耗时，验证 Stop 时界面保持响应。研发在冻结环境与样本后提出预算、测量方法及阈值并经评审；没有基线时不把未经测量的数字写成已达标。
  • 可访问与国际化：至少完成中英文的实际界面、菜单、错误与恢复动作验证；键盘可达、焦点顺序、可见焦点、缩放与目标快捷键逐项对照。支持哪些额外语言按目标和 Friday 实际资源登记。
  • 离线与网络：本地编辑和保存不应因外部模型或搜索不可用而无故失效；需要网络的模型、资源和服务准确显示状态，重连后可恢复。
  • 兼容性：候选须在约定 Windows 环境干净安装并与旧版升级；原四类 Office、文件关联、打开偏好、用户文件、会话和 PDF 专项不回归。其他平台支持须单独列验收，不由 Windows 成功外推。

8. 测试数据、证据与发布门槛

测试集至少包含空白页、静态文章和复杂 CSS、脚本交互及动态节点、Unicode 和中英文路径、同名多目录、本地/远程/缺失图片、多个附件和长文本、外链与恶意协议、损坏文件、只读/占用目标、大 DOM 及慢网络。为每份数据记录授权、来源、哈希、适用条件和预期；真实用户文档应经授权并排除敏感信息。

验收分为：固定上游参考行为；单元与合同；开发版真实 renderer/preload/host；真实模型与配置有效的外部服务；人工真实操作；无源码的安装包；旧版升级和回滚。每层分别留证，不用 mock、源码静态存在或单一截图替代其他层。AI 至少覆盖生成、局部修改、附件、搜索、取消、失败及恢复；有条件的工具须有真实有效配置的成功证据。GUI/CLI/打印分别留产物、摘要及可打开验证。

发布必须同时具备：冻结的上游 tag/commit 与差异审计；HTML-01～12 逐子项 100% 映射并按目标条件通过；新旧入口和四类 Office 回归；安全、隐私、故障及性能证据；已提交且可取得的 Friday/vendor 源码身份、匹配资源与包 hash；干净安装、升级、用户数据保留和整套回滚报告。测试记录须包含样本/配置标识、源码与包身份、系统环境、实际操作、结果和复核人。缺条件或未测记为阻塞/待验收，不能标为通过或不适用。

回滚以主程序、vendor、Office 资源、配置协议和数据兼容性为一个匹配组合；保留用户 HTML、素材、已导出文件和会话，不覆盖新产生的数据。旧版无法编辑新模块时，应明确保留文件和可恢复路径。公开发布、安装包生成及上游融合分别以各自实际证据声明。

  1. 目标与参考冻结：重新核验官方候选；审计 v0.12.600 与候选的 HTML 差异，产出完整能力台账、参考运行和依赖/许可证清单。禁止凭候选名称暗示已融合。
