# 剪贴板钉窗增量验收

日期：2026-10-24。源码版本：3.0.6-preview.2。仅使用独立临时数据和测试窗口，未改安装版或用户数据。

## 修复

- 同条目再次指定展开或缩略打开时，主进程只调整尺寸，没有通知现有页面更新模式，导致大窗口内仍显示缩略内容。复用窗口时推送原 clipboard-pin-changed 事件，同步实际内容。
- 钉窗刷新采用请求序号，旧图片响应不能在后来的编辑或状态变化之后覆盖新缩略图；打开中的右键菜单同时读取最新收藏等状态。
- 钉窗内隐藏“钉到屏幕”这一无动作的重复命令，主剪贴板菜单仍保留正常钉窗入口。
- 展开、缩略、关闭和二维码图标按钮补齐可访问名称，继续沿用 FridayButton、现有原版菜单和详情弹窗。

## 证据

运行 npm run dev 后执行 node scripts/probe-clipboard-pins.mjs。Node 父进程在 Electron 释放 Chromium profile 后，通过不跟随链接删除函数清理测试目录。探针隐藏窗口，不操作用户鼠标或系统剪贴板。

| 范围 | 已验证结果 |
| --- | --- |
| 真实页面与主进程 | 实际独立 BrowserWindow、Vue、正式 preload 和注册的 clipboard IPC |
| 重复打开 | 同条目只保留一个窗口，展开状态与页面内容同步 |
| 缩略右键 | 自动展开并显示原菜单；无重复钉窗空命令 |
| 收藏与菜单 | 写入数据库，打开中的菜单可更新为取消收藏；Esc 关闭 |
| 跨窗口更新 | 修改备注后自动刷新，详情保留最新备注 |
| 屏幕工作区 | 从右下边界展开/缩略后，窗口边界限制于实际工作区 |
| 图片 | 受管真实 PNG 缩略图解码、展开使用原预览组件 |
| 异步竞争 | 人为延迟旧图片响应，再保存另一张真实 PNG；新缩略先到后，旧结果不能覆盖 |
| 暗色详情 | 对真实 DOM 检查主题和弹窗边界；通过 CDP 实际截图后人工查看 |
| 删除和关闭 | 原条目删除自动关闭对应钉窗，另一个窗口关闭后数量回到初始宿主 |

红证据：app-data/diagnostics/clipboard-pins-before.log，明确超时于“复用钉窗的展开模式同步”。修复后阶段证据：clipboard-pins-after.log。最终含重复命令过滤的验收：clipboard-pins-final.log。截图：app-data/diagnostics/clipboard-pin-detail-dark.png。

最终探针退出 0；最终前端构建通过（47.02 秒，app-data/diagnostics/clipboard-pins-build-final.log），git diff --check 与两个相关主进程/探针文件语法检查通过。

最早一次探针冷启动编译超时，第二次夹具图片名称未遵循受管 SHA256 命名规则，二者不当作产品缺陷或通过证据。原 capturePage 对隐藏窗口返回旧帧，已改为 CDP 截图并人工查看实际深色详情；旧帧不作视觉验收。

## 未完成的系统范围

- 原生可见窗口的实际置顶、鼠标拖动、触控板和多显示器变化仍未验证。探针只证明 CSS 原生拖动区域与按钮非拖动区域配置，绝不把它替代为实际拖动。
- 最终安装版的同一路径仍需验收；本报告不代表完整剪贴板系统门禁通过。
