# Friday Office AI 业务能力与 PDF 转 Word 产品需求 PRD

日期：2026 年 11 月 5 日。版本：1.0。状态：待实施与评审的产品合同。本文件中的“必须”表示发布条件，不表示当前软件已实现。

本版目标是使用户在 Friday 中通过转换按钮、PDF AI 面板和主助手发起 PDF 转 Word 时，使用相同业务能力并获得真实可用的 DOCX。同时解决已公开的创建 Word 能力失败与结果假成功问题，建立后续功能按统一契约接入的基础。原 GenOffice 全面升级及 Markdown、HTML 功能对等需求继续保留，本版不以完成全部 Office 功能迁移为前提。

本次方案还必须支持后续持续融合 GenOffice 新版本：Friday 的权限、任务与交付逻辑保留在宿主，vendor 差异收敛为可追溯的通用接口；上游新模块通过受控 adapter、构建 manifest 与对等验收进入产品。

配套研究报告负责事实依据，技术拆解负责实现与工程任务。本文作为验收标准，研发不能只以工具返回 ok 或按钮可点击作为完成依据。

## 1 产品问题与用户价值

用户已经在界面上看到 PDF 转 Word 功能，因此合理预期 AI 可以完成同一操作。实际却得到“当前环境不支持创建文档”。这种差异会使用户无法判断 AI 的能力边界，也无法区分请求失败、生成失败和文件打开失败。

本版应让用户能够用自然语言完成既有转换操作，知道系统正在处理哪份文件、输出到哪里、是否可编辑，以及出现问题后应该如何继续。对于尚未接通的功能，要在执行前给出具体原因，不能先假装支持再让模型反复尝试。

长期价值是降低新增能力的重复接入成本，而不是让 AI 对所有操作无限制执行。转换算法、编辑器支持和授权边界仍需真实实现。

## 2 目标与不纳入本版的范围

### 2.1 必须交付

| 范围 | 本版交付 |
|---|---|
| PDF→DOCX | 本地转换，按钮与 AI 共享领域执行器 |
| PDF 面板转换工具 | 根据真实宿主能力提供转换操作，不用 create_document 冒充转换 |
| 从内容创建 DOCX | 修复 PDF 面板已宣称支持的创建动作，等待保存和文件回读 |
| 统一能力查询 | 菜单、AI schema、执行校验和诊断使用同一版本化描述 |
| 文件与任务闭环 | 源保护、取消、幂等、错误、质量告知、打开状态 |
| 主助手接入 | 当前 PDF 的同一转换语义进入共用服务；离线源经授权适配 |
| 发布验证 | 开发与安装环境验证、构建清单和回归证据 |

### 2.2 后续范围

PDF→Excel、PDF→PPT 的完整产品接入与质量验收；六类编辑器全部操作迁移；Markdown 与 HTML 完整应用功能对等；任意 Office 格式互转；全新 OCR 引擎；云端转换服务；系统级鼠标自动点击。

本版必须识别这些能力的真实可用状态，并消除错误宣传。它们在原总体规划中的需求不被本文件取消。PDF 转换算法若暴露 P0 数据损失或完全不可用缺陷，仍属于本版修复阻塞项，不能以“算法不在范围”推迟。

## 3 产品对象与术语

| 名称 | 产品含义 |
|---|---|
| 转换 | 从指定源文档快照产生目标格式，保留其内容，不由模型自由重写 |
| 创建 | 把用户或模型提供的内容写成新的文档 |
| 文档资源 | 带稳定身份和版本的文件或打开的编辑器实例 |
| 能力 | 有明确输入、权限、实现、输出与可用条件的业务操作 |
| Artifact | 已提交、通过校验、可被定位的输出文件 |
| 打开 | 在 Friday 标签页展示已生成文件，独立于文件生成是否成功 |
| 降级 | 文件已生成，但部分文字或结构以图片等较弱形式保留 |
| 暂不可用 | 能力有定义但当前运行环境、文档状态或授权不满足条件 |

“Word 文件生成成功”至少表示 DOCX 已落盘且回读合格。“已打开”还要求 Friday 成功加载对应资源。两句话不应混用。

## 4 用户与典型场景

### 4.1 主要用户

需要把收到的 PDF 继续编辑的普通用户；通过 AI 助手整理材料的用户；以 Office 处理合同、表格和扫描材料的高频用户；需要定位失败原因的支持与测试人员。

### 4.2 用户故事

| ID | 用户故事 | 验收关注点 |
|---|---|---|
| US01 | 我只打开 PDF，直接告诉 AI“把这份转成 Word” | 冷启动可执行，不要求先打开 Word |
| US02 | 我点击转 Word，再用 AI 做相同操作 | 同源能力、同样权限和质量规则 |
| US03 | 我修改 PDF 后转换，希望包含刚才的编辑 | 使用当前已确认快照，不偷偷保存覆盖源 |
| US04 | 我在长任务期间切换标签 | 不串文档，能看见任务来源与进度 |
| US05 | 我取消保存位置或密码输入 | 结束任务，不报成功、不自动重试 |
| US06 | 我重复发送同一句指令或网络重试 | 不重复转换、弹窗和覆盖 |
| US07 | 我的 PDF 是扫描件 | 清楚知道输出是否含可编辑文字 |
| US08 | 文件生成后 Word 标签打不开 | 可以找到已生成文件并重试打开 |
| US09 | 我让 AI 把摘要写成 Word | 走创建语义，内容不是整份 PDF 的替代转换 |
| US10 | 我要求转 Excel，但本版未接通 | 执行前准确告知，无无效调用循环 |
| US11 | 我在主助手说“把当前 PDF 转成 Word” | 绑定 Office 当前资源，经同一领域服务执行 |
| US12 | 我把一份磁盘 PDF 交给主助手转换 | 先验证文件授权，再走同一转换能力 |

## 5 端到端体验

### 5.1 转换标准流程

1. 用户点击转 Word 或提出转换要求。
2. 系统确认源文档身份、当前能力与必要授权。当前只有一份明确 PDF 时不重复询问文件。
3. UI 显示源文档名称和转换目标。多份附件且指代不明时只询问源文件。
4. 获取源快照与版本。若必须先保存才能取得完整内容，应明确说明并由用户决定；不能未经授权覆盖原 PDF。
5. 选择或确认输出位置。已确认路径可复用，新增覆盖仍需确认。
6. 执行本地转换。密码通过本地交互提交，不经模型上下文。
7. 校验 DOCX、提交文件、登记 artifact，再尝试在 Friday 中打开。
8. 返回实际文件位置、质量提示和打开状态。必要时提供打开、定位文件或重试打开操作。

### 5.2 摘要创建流程

系统先读取授权源内容，模型生成摘要；创建操作只接收摘要内容与文档类型，使用创建流水线交付。工具回传保存结果之前，AI 不得声称“已生成文件”。如果生成内容为空、导入失败或保存失败，应返回对应原因，而不是提交空白 DOCX。

### 5.3 提交后的异常流程

目标文件已提交而标签打开失败时，任务状态是“已生成，打开失败”，不回滚或删除已经交付的文件。重试动作只重试打开，不能重新执行转换。应用关闭前已经提交的结果应能在任务记录中找到。

### 5.4 不支持功能的流程

菜单可以保留转 Excel、转 PPT 位置，显示禁用原因“此版本尚未接入”。AI 请求的工具 schema 不包含这些输出格式。用户直接问起时，助手说明具体缺口；不得声称整个环境都不能创建文件，也不得不断调用必失败工具。

## 6 详细功能需求

### 6.1 能力发现与一致性

| ID | 优先级 | 需求与验收 |
|---|---|---|
| CAP01 | P0 | 同一能力描述提供操作 ID、版本、输入输出格式、可用条件、风险和结果语义；按钮、AI 与执行器不得各写一份支持列表 |
| CAP02 | P0 | 执行前重新校验实时能力；查询后文档关闭、授权撤销或引擎失败时返回可理解状态 |
| CAP03 | P0 | 支持、暂不可用、未实现和无权限可区分，提供 reasonCode 与建议动作 |
| CAP04 | P0 | 模型请求只暴露当前文档类型和权限范围内的工具及格式，不把六类编辑器所有工具一律注入 |
| CAP05 | P0 | 启动或 CI 检查宣称支持却无 handler、parser 枚举不一致、结果合同不符等问题 |
| CAP06 | P0 | 能力查询不能只因 Docs 尚未加载就称 DOCX 不支持；可懒加载与缺失依赖必须区分 |
| CAP07 | P1 | 管理诊断展示遗留能力和迁移覆盖率；分母是已盘点的业务操作，不是含糊的“所有功能” |

### 6.2 请求意图与资源绑定

| ID | 优先级 | 需求与验收 |
|---|---|---|
| SRC01 | P0 | “这份 PDF”绑定发起消息时的资源 ID，不依赖稍后执行时的全局活动标签 |
| SRC02 | P0 | 记录 source revision 与操作快照；未保存编辑不得被静默遗漏 |
| SRC03 | P0 | 转换本身不得改写源文件；如用户另行选择保存，应将保存与转换作为两个清楚的动作 |
| SRC04 | P0 | 快照未完成前文档变化应重新确认或重取；快照完成后处理固定版本，进度中说明其版本 |
| SRC05 | P0 | 多 PDF 或多附件且指代不明时询问选择，不擅自使用最近文件 |
| SRC06 | P0 | renderer 调用只能操作其拥有或被授予的文档；主助手文件访问遵守现有沙箱和用户授权 |
| SRC07 | P0 | 源 PDF 被移动、外部修改或失效时，使用已冻结快照或明确失败；不得读取另一路径的替代文件 |
| SRC08 | P0 | 只读及加密权限遵循既有政策，转换不成为绕过限制的方式 |

### 6.3 转换与创建

| ID | 优先级 | 需求与验收 |
|---|---|---|
| DOC01 | P0 | PDF→DOCX 不需要模型重新生成全文，原生转换由共享 converter 执行 |
| DOC02 | P0 | PDF 按钮、PDF AI 和主助手同一路线使用同一领域服务，输入不同只由 adapter 处理 |
| DOC03 | P0 | 只打开 PDF 的冷启动可创建或转换 DOCX，Docs 按需初始化，结果在 Friday 标签中打开 |
| DOC04 | P0 | 创建 DOCX 等待内容导入、序列化、写入和回读，不能在标签排队时返回完成 |
| DOC05 | P0 | 无有效内容节点或导入错误时不交付空白成功文件；保留具体失败原因 |
| DOC06 | P0 | 转换与创建返回不同 operationId，历史中可分辨内容来源 |
| DOC07 | P0 | 不新增独立 GenOffice 窗口，不让上游 standalone 回退意外接管 Friday 标签生命周期 |
| DOC08 | P0 | 当前未实现的 html 或其他创建类型不在可执行 schema 中，消除声明与 parser 差异 |
| DOC09 | P0 | 已有可用 pdf、md 创建能力不得无说明被破坏；按宿主实测状态保留或提供具体暂不可用原因 |
| DOC10 | P1 | 新格式仅新增路由 adapter 与契约样本测试，即可通过同一目录进入多个入口 |

### 6.4 文件交付与结果

| ID | 优先级 | 需求与验收 |
|---|---|---|
| OUT01 | P0 | 输出为实际 DOCX，不以修改扩展名、文本文件或仅新建标签作为成功 |
| OUT02 | P0 | 验证 ZIP 关键部件、document XML 可解析及 fixture 内容回读；仅判断文件非零不够 |
| OUT03 | P0 | 输出 artifact 包含任务 ID、路径、类型、大小、源版本、质量、持久化状态和打开状态 |
| OUT04 | P0 | 输出不得覆盖源 PDF；同名文件覆盖需确认，确认必须绑定目标和当时文件身份 |
| OUT05 | P0 | 写入使用临时文件和可恢复提交；失败不损坏已有目标，不留下被当作成功结果的半文件 |
| OUT06 | P0 | 已提交但打开失败时保留文件，显示可定位路径与重试打开入口 |
| OUT07 | P0 | 文件路径、标题、资源 ID 和标签标题保存后同步；同名不同目录不混淆 |
| OUT08 | P0 | 标题中的非法字符被规范化，扩展名由格式确定；拒绝路径穿越、源路径别名覆盖等情况 |
| OUT09 | P0 | AI 最终回复依据结构化结果，失败或取消不得生成伪造下载链接或声称已创建 |

### 6.5 任务与错误

| ID | 优先级 | 需求与验收 |
|---|---|---|
| TASK01 | P0 | 显示准备、等待授权或输入、转换、校验、保存、打开及终态；不以随机百分比替代真实阶段 |
| TASK02 | P0 | 支持保存对话框取消、密码取消和执行取消；提交前取消不产生最终 artifact |
| TASK03 | P0 | 同一请求重试复用任务或结果，不能重复保存弹窗、转换与覆盖 |
| TASK04 | P0 | 同源冲突有明确 busy 或排队结果；不同源任务也不能突破经过验证的全局内存并发限额 |
| TASK05 | P0 | 发起视图在准备阶段关闭时取消；快照完成后普通切换标签不取消，显式取消仍有效 |
| TASK06 | P0 | 转换器无安全中断能力时提示“正在停止”，结果不得晚到后被提交；长时间无响应可终止隔离进程 |
| TASK07 | P0 | 超时、崩溃与应用重启后不盲目重放覆盖操作；恢复时查询已有提交结果 |
| TASK08 | P0 | 已进入不可中断提交阶段时说明状态；提交已完成则返回文件结果，不虚报取消成功 |
| TASK09 | P0 | 错误有稳定 code、阶段、可恢复性和 nextAction，界面提供中英文文案 |
| TASK10 | P0 | 不把操作取消归类为网络或模型错误，不自动让模型重复执行 |
| TASK11 | P0 | 所有路径释放锁、临时文件、renderer 等待器和子进程；清理失败可诊断但不能删除已有用户数据 |
| TASK12 | P1 | 支持从任务记录直接重新打开或定位结果；重启后是否继续转换由安全恢复策略决定 |

## 7 交互状态与示例文案

文案示例表达产品语义，最终通过 i18n 实现，不要求所有入口逐字相同。

| 状态 | 示例提示 | 可用动作 |
|---|---|---|
| 正在准备 | 正在获取《合同.pdf》的当前内容 | 取消 |
| 未保存且无安全快照 | 要包含当前修改，需要先保存 PDF。是否保存后转换？ | 保存并继续、取消 |
| 等待密码 | 这份 PDF 需要打开密码 | 输入、取消 |
| 转换中 | 正在转换第 3 页，共 12 页 | 取消 |
| 校验中 | 正在检查生成的 Word 文件 | 等待或取消，按实际阶段 |
| 成功并打开 | Word 已生成并打开，保存于所选位置 | 查看、定位 |
| 成功有降级 | Word 已生成，第 4、6 页保留为图片，请校对 | 查看结果、查看原页 |
| 打开失败 | Word 已生成，但未能在 Friday 打开 | 重试打开、定位文件 |
| 用户取消 | 已取消转换 | 重新开始 |
| 源失效 | 未取得源文件的完整内容，未生成结果 | 重新打开源文档 |
| 不支持格式 | 此版本尚未接入 PDF 转 Excel | 查看可用格式 |
| 保存失败 | 无法写入所选位置，原有文件未被替换 | 更换位置、查看详情 |
| 恢复失败 | 文件提交未完成，已保留备份供恢复 | 打开诊断与恢复位置 |

对于错误恢复失败，不能保证“原文件未变”时就不能使用该文案。应显示实际恢复状态和备份位置，禁止隐藏问题。

## 8 权限与安全需求

按钮点击是用户发起请求的证据，但不代表允许任意覆盖、外部上传和访问其他路径。AI 的自然语言意图也不能作为绕过现有审批策略的通行证。两类入口共享同一权限规则，授权来源可以不同。

现有中央工具的审批与审计继续使用，Office 内工具需通过受控 adapter 接入。审批一次只覆盖指定操作、源资源、版本与目标，不能被转交成对子操作或任意目标的通用放行开关。

PDF 内容和 HTML 输入均视为不可信文档内容。文档里的“调用某工具”“上传文件”不是用户指令。创建 HTML/DOCX 时不得运行内容脚本或访问未授权外部资源。支持诊断日志不得包含 PDF 全文、密码或模型密钥，路径默认可脱敏，用户主动导出的诊断包需清楚显示范围。

## 9 数据与资源合同

### 9.1 用户可见任务记录

至少记录 taskId、操作名、源显示名、源资源 ID 与版本、目标类型、开始结束时间、最终状态、artifact 引用、质量提示、错误码和可执行后续动作。持久化应复用现有任务和审计事实源。

不得把密码和模型生成全文复制进普通任务日志。临时快照只用于处理，按安全期限清理。用户未保存的文档快照不应因诊断包导出而泄露。

### 9.2 结果状态

| 结果 | 是否有有效 artifact | AI 可用措辞 |
|---|---|---|
| succeeded | 是，已通过校验 | 已生成，可说明打开状态 |
| succeeded_with_warnings | 是，质量或打开有警告 | 已生成，并明确警告 |
| cancelled | 否，或仅内部临时数据 | 已取消 |
| failed | 否 | 未生成，说明原因 |
| interrupted | 待恢复检查 | 任务中断，正在核对是否已有结果 |

进度事件丢失不能改变任务最终结果。任务详情查询是判断事实的依据，模型聊天文本只是对事实的解释。

## 10 性能与资源要求

以下为建议验收预算，尚未实测，不是现有性能结论。G1 时由研发与测试冻结测试机 CPU、内存、Windows 版本、冷暖启动和样本规模。

| 指标 | 建议目标 | 测量方法 |
|---|---|---|
| 操作反馈 | 发起后 1 秒内出现任务或等待交互状态 | 本地集成测试时间戳 |
| 能力查询 | 暖态 p95 不超过 200 ms | 固定机器重复查询，排除首次引擎加载 |
| 冷启动 | 3 秒内可见正在加载，不得无反馈等待 | 仅 PDF 已加载的冷启动 |
| 取消反馈 | 请求后 1 秒内进入停止或取消态 | 执行取消注入；不等同子进程终止耗时 |
| 界面响应 | 转换期间不出现持续超过 1 秒的输入阻塞 | UI 心跳与主进程延迟采样 |
| 内存与大文件 | 在声明限制内不 OOM，超限执行前拒绝或说明 | 页数、文件大小、峰值 RSS 记录 |
| 转换耗时 | 按数字、扫描、混合三类建立 p50/p95 基线后定阈值 | 不能用单个合成 PDF 推断 |

建议首期将转换全局并发设为 1，源与目标另加锁；是否增加并发由峰值内存和事件循环实验决定。文件大小和页数上限应在性能实验后配置并进入能力查询，不在文案里给出未经验证的支持规模。

## 11 样本体系与质量验收

### 11.1 样本分组

| 组别 | 最低覆盖 |
|---|---|
| A 数字文本 | 单页英文、多页中文、混合中英、特殊符号、数字日期 |
| B 结构 | 标题、列表、简单与跨页表格、双栏、页眉页脚、图片 |
| C 扫描 | 清晰扫描、低质量扫描、混合文本与扫描、多语言 |
| D 加密 | 需密码、错密码、取消、已授权但只读情况 |
| E 文件系统 | 中文空格路径、同名不同目录、目标占用、无权限、磁盘故障注入 |
| F 生命周期 | 未保存修改、切换标签、关闭源、应用退出、renderer 崩溃 |
| G 负载 | 多次请求、大页数、大图片、超出限制 |
| H 创建 | 标题正文、表格列表、空内容、无有效节点、序列化与保存错误 |

样本必须带授权来源，优先合成或脱敏。用户文件只能在用户授权范围内保存和分析，不能随测试提交到公开仓库。

### 11.2 质量通过标准

固定数字文本 fixture 的唯一标记、数字和正文完整回读，关键字段不得遗漏、篡改或重复；预期段落、表格和图片存在。合成中文样本采用明确的可编辑文本断言。

真实复杂文档采用人工标注关键字段与页对应关系，文本、结构、版面分别评分。评分阈值在样本冻结后确定，不将研究阶段的建议值当实测。扫描无 OCR 时不要求凭空产生文字，但必须判定 imageOnly 或 mixed 并展示警告；不能算作“完整可编辑转换”通过。

相同源经按钮和 AI 的结果以语义与质量对照，不要求 DOCX ZIP 字节完全相同，避免时间戳和元数据造成无意义差异。

## 13 指标与发布口径

目标是专项验收中 P0 全部通过，不以统计成功率掩盖确定性失败。真实使用指标可记录请求成功率、取消率、错误分布、重复副作用次数、保存后打开失败率、转换质量警告占比和任务耗时。

“重复副作用次数”应为零；“报告成功却无有效文件”应为零。架构覆盖率只对本版明确迁移的操作计算，不得用 PDF 两条能力完成就写成“Office 全面 AI 原生化完成”。不采集文档全文来统计这些指标。

性能目标和转换质量阈值在 G1 冻结，安装版观察窗口与灰度用户数量由发布计划决定。未定义统计窗口时，不写“线上成功率已达 99%”等无证据结论。

## 15 回滚与兼容

新目录按 capability version 和 feature flag 控制，不同入口对同一操作必须一起切换。回滚不能让按钮使用新执行器而 AI 回到已知坏回调。新创建能力若不可用，应准确降级为暂不可用，而非恢复虚假支持。

数据库迁移只新增兼容字段或使用现有可扩展结构，保留旧任务和会话。回滚不得删除用户已生成文件。若候选版本出现文件损坏、源覆盖或错误成功，应暂停相应写能力并保留只读和可用的原操作。

## 16 文档与总体项目关系

原三份 GenOffice 升级文档、旧 PDF 专项文档和已有 AI Core 总体文档均保留。本版三份新文档描述当前发现与新的实施合同，后续只在本目录迭代其版本和变更记录，不把旧报告内容改写成“当时已经知道”。

Markdown、HTML 的完整对等功能继续按总体文档追踪。本版为它们提供可复用的能力接入方法，但不能用能力层完成替代两个应用的入口、编辑器、构建、资源、工具和格式质量验收。

## 17 发布前必须回答的问题

需要研发和测试明确：源快照如何覆盖未保存编辑；创建 DOCX 的保存确认是否可靠；能力目录是否映射到实际构建资源；OCR 缺失时如何告知；取消是否能阻止晚提交；断电恢复是否保护旧目标；主助手与内嵌 AI 的审批是否一致；安装版是否仍依赖开发路径。

这些问题都有技术任务与验收项。它们不是要求用户逐个做技术选择，而是研发必须通过实现和证据解决的交付责任。

## 18 持续融合 GenOffice 的产品与工程合同

### 18.1 维护目标

用户后续要持续跟进 GenOffice 的新模块和功能。本次修复应降低重复接入与升级冲突，而不是锁死当前定制版本。长期目标为“固定版本、可追溯融合、可验证功能对等”，不承诺未经评估自动合并任意上游变更。

2026-11-05 补充核验：官方 releases/latest 指向 v0.12.852，tag 引用 SHA 为 4b55db9ed1994575a695160ffc6cfd0bfc866211。它是后续全量升级的评估候选；原 v0.12.600 总体文档保留为历史基线，不将旧差异统计直接转用于新候选。上游发布说明提到 PDF→Word 的重复页眉与连续页码改进，后续需纳入转换质量回归，不能视为 Friday 宿主创建接口已修复。来源与验证边界见研究报告第 2、13、14 节。
